# История изменений

Все значимые релизы trip2g. Самый свежий — сверху. Для каждого изменения указано
**Что / Зачем / Как использовать**, чтобы оператор или администратор мог решить,
стоит ли обновляться и как начать пользоваться функцией.

Теги старее `v0.2.0` доступны только в истории git.

## v0.7.1 (2026-06-26)

### Полноширинные страницы (`wide: true`)

- **Что.** Любую заметку теперь можно отрисовать на всю ширину, добавив `wide: true` во frontmatter — страница убирает обе боковые панели и узкую читаемую колонку, и контент занимает всё основное поле.
- **Зачем.** Широкий контент — kanban-доски, большие Mermaid-диаграммы, широкие таблицы — был зажат в дефолтной колонке 65ch.
- **Как.** Добавьте `wide: true` во frontmatter заметки. Гайд: [[ru/user/default-template]].

### Инструмент превью layout-ов: `trip2g-preview` — замена `renderlayout.py` (`19483421`, `d0fe4179`)

- **Что.** Новый standalone node-CLI `scripts/trip2g-preview.mjs` рендерит Jet-layout против заметки через `/_system/renderlayout` и добавляет режим `--watch`: пере-POST-ит при каждом сохранении, а открытая по `?live` страница перезагружается сама. Заменяет старый `scripts/renderlayout.py` (удалён) — без зависимости от Python.
- **Зачем.** Ускоряет цикл вёрстки: правишь `_layouts/*.html` — сразу видишь результат, ловишь ошибки Jet в терминале. Работает против любого сервера — локального memcli (читает `data.json`) или удалённого/staging через `--api-url`/`--api-key`.
- **Как.** `node scripts/trip2g-preview.mjs --watch --layout-file _layouts/article.html --note-path /about`, затем открыть напечатанный `?live` URL (с memcli сначала `memcli open`, чтобы браузер был залогинен). Гайд: [[ru/user/renderlayout]]; два локальных дизайн-цикла описаны в `docs/dev/local_design_iteration.md`.

### memcli: изолированные инстансы через `--name` (`5f0542f8`, `353841e0`)

- **Что.** `memcli up --name <id>` поднимает второй инстанс в своём контейнере `trip2g-memory-<id>`. Тот же `--name` передавайте в `down`/`status`/`logs` и задавайте отдельный `--port`. Без `--name` поведение по умолчанию (`trip2g-memory`) не меняется.
- **Зачем.** Позволяет держать несколько локальных memcli-инстансов рядом (например, по одному на vault), не конфликтуя за единственное захардкоженное имя контейнера.
- **Как.** `node cli/memcli/dist/memcli.js up --folder ./v2 --name v2 --port 24381`. Состояние — отдельное на каждый `--folder`. Гайд: [[ru/user/memcli]].

## v0.7.0 (2026-06-23)

### Режим read replica (`a4423895`)

- **Что.** Второй инстанс trip2g теперь может работать как реплика только для чтения. Задайте `TRIP2G_LEADER_ADDR` на нём: он будет обслуживать все GET-запросы из локальной копии SQLite (реплицируемой через LiteFS) и пересылать каждую запись на первичный инстанс.
- **Зачем.** Это снижает задержку на чтение при нагрузке на primary, позволяет перезапускать primary без потери ни одного читательского запроса и открывает возможность горизонтального масштабирования на отдельных машинах. В тестах во время перезапуска лидера не было зафиксировано ни одного сбоя чтения на реплике.
- **Как.** Запустите LiteFS на обоих серверах (реплика получает потоковую копию WAL SQLite). Запустите реплику с `--leader-addr=http://10.x.x.x:8082 --leader-shared-secret=...`. Значение `--leader-shared-secret` должно совпадать с `TRIP2G_LEADER_REPLICA_SECRET` на primary. Полная инструкция по настройке: [[ru/user/read-replica]].

### Вход через OIDC / корпоративный SSO (`1d2b12b5`, `b6446f76`, `e6d7afe9`)

- **Что.** Пользователи теперь могут входить с корпоративной учётной записью через Authentik, Keycloak или любой стандартный OpenID Connect-провайдер. На странице входа появляется кнопка «Войти через SSO», когда OIDC-провайдер настроен. Автопровизиинг опционален: при включении валидная идентичность IdP создаёт пользователя trip2g автоматически; при отключении пускаются только предварительно заведённые аккаунты.
- **Зачем.** Команды с корпоративным IdP больше не управляют отдельными паролями trip2g, а MFA обеспечивает сам IdP.
- **Как.** Задайте `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` и `OIDC_DISCOVERY_URL` на сервере. Строка в базе данных не нужна: провайдер читается из переменных окружения при каждом запросе. CRUD учётных данных администратора доступен через GraphQL-мутации для установок, которым это нужно. Полная инструкция: [[ru/user/oidc]].

### Хранилище на локальной файловой системе (`0f5b84e2`)

- **Что.** Trip2g теперь может хранить загруженные ассеты (изображения, вложения) на локальной файловой системе вместо S3 или MinIO. Задайте `STORAGE_BACKEND=local` (или `--storage-backend=local`) и при необходимости укажите путь через `STORAGE_LOCAL_PATH`.
- **Зачем.** Работа без объектного хранилища убирает главную внешнюю зависимость для одиночного сервера. Дешёвый VPS с подключённым томом становится полноценным автономным деплоем.
- **Как.** Добавьте `STORAGE_BACKEND=local` в файл переменных окружения. Путь по умолчанию: `./data/storage`; переопределите через `STORAGE_LOCAL_PATH`. При переходе с S3 нужно предварительно скопировать содержимое бакета в локальный путь. Полная инструкция для одного сервера: [[ru/user/local-quickstart]].

### Деплой без даунтайма (`08a6cfde`, `22dd8cf3`)

- **Что.** Trip2g теперь поддерживает socket activation systemd (`LISTEN_FDS`) и публикует два health probe на отдельном внутреннем порту: `/livez` (всегда 200, даже в период прогрева) и `/readyz` (503 до тех пор, пока инстанс не прогрелся, и снова во время дрейна). Вместе они дают балансировщику или оркестратору сигналы, необходимые для переключения трафика со старой версии на новую без потери запросов.
- **Зачем.** Раньше при rolling restart возникал разрыв: старый процесс уже останавливался, пока новый ещё прогревал кэш заметок. Теперь новый инстанс прогревается параллельно, и трафик переходит только после того, как `/readyz` вернул 200.
- **Как.** Добавьте socket unit в systemd, чтобы ОС удерживала порт в момент перезапуска. Задайте `--internal-listen-addr=:8081` и настройте балансировщик на ожидание `/readyz` перед маршрутизацией. `--shutdown-grace-period` управляет тем, как долго старый инстанс продолжает обслуживать запросы после того, как `/readyz` переключился на 503. Используйте `--simple-backup-on-shutdown=false`, чтобы пропустить финальный бэкап во время rolling restart. Готовые рецепты (Nomad/Traefik, Caddy, k3s): [[ru/user/zerodowntime]].

### memcli: CLI для агентной памяти (`a4e6fd1e`, `951d52ed`)

- **Что.** `memcli` — это CLI-утилита, которая одной командой поднимает инстанс trip2g как долгосрочную память для AI-агентов. Одна команда (`node memcli.js up --folder ./memory`) запускает Docker-контейнер с локальным хранилищем, создаёт admin-ключ через HAT, стартует sidecar `trip2g-sync --watch` и записывает заметку `hub.md` в memory-vault. Подкоманда `hub` и MCP-инструмент `memory_bind_hub` привязывают инстанс к удалённому federation hub, чтобы поисковые запросы агента охватывали федеративные базы знаний через единственный MCP-эндпоинт.
- **Зачем.** Раньше настройка отдельного trip2g для агента требовала четырёх ручных шагов (сервер, ключ, синхронизация, MCP-конфиг). memcli сворачивает их в одну команду. Скомпилированный `dist/memcli.js` поставляется в репозитории, шаг сборки не требуется.
- **Как.** `node cli/memcli/dist/memcli.js up --folder ./memory-vault`. После завершения MCP-эндпоинт доступен по адресу `http://localhost:24081/_system/mcp`. Добавьте его в `.mcp.json` вашего агента. Полная документация: [[ru/user/agent-memory]].

### Стабильность gitapi-зеркала (`2845bb82`, `8082c24d`)

- **Что.** Два исправления в зеркале DB→git (gitapi). Если вызов `materialize` завершается с ошибкой на полпути, осиротевшие loose-объекты теперь очищаются перед возвратом ошибки. После успешного `materialize` сразу запускается gc для упаковки loose-объектов. Раньше неудачные запуски могли оставлять orphaned-файлы, накапливавшиеся с каждой ночной перестройкой и в итоге заполнявшие диск.
- **Зачем.** На инстансах с большим числом заметок повторные сбои materialize приводили к бесконтрольному росту директории git-данных. У операторов с небольшим VPS возникало давление на диск, требовавшее ручной очистки.
- **Как.** Ничего делать не нужно. Оба поведения автоматические после обновления. Если наблюдался рост диска от осиротевших объектов, запустите `git gc --prune=now` в директории репозитория (или дождитесь следующего запуска materialize при перезапуске сервера).

## v0.6.1 — 2026-06-22

### Живые обновления в плагине Obsidian (плагин v0.5.0)

- **Что.** Плагин trip2g sync теперь использует подписку `noteChanges` (появилась в v0.6.0) и подтягивает изменения с сервера в хранилище в реальном времени — без нажатия синхронизации и без ожидания периодической проверки.
- **Зачем.** Для работы с нескольких устройств и правок агентами изменение на сервере (или на другом устройстве) появляется в Obsidian за секунду, а не после следующего опроса. Это выигрыш в UX — мгновенная свежесть и меньше холостого трафика, — а не в сырой скорости: запрос списка заметок и так был чтением по индексу на ~10 мс.
- **Как.** Обновите плагин до 0.5.0 (через BRAT), включите **Two-way sync**, затем задайте **шаблоны Live pull** в настройках плагина (include/exclude по glob, например `**`, или `blog/**` с исключением `drafts/**`). Безопасность сохранена: локальные правки никогда не перезаписываются (показывается окно конфликта), а удаление на сервере сначала спрашивает. Опрос раз в 60 секунд заменён на более лёгкую сверку-страховку раз в 5 минут. Документация: [`docs/ru/user/Двухсторонняя синхронизация.md`](./user/Двухсторонняя%20синхронизация.md). История: [`docs/ru/thoughts/sync-benchmark.md`](./thoughts/sync-benchmark.md).

### Намного быстрее массовая и CLI-синхронизация заметок с ассетами

- **Что.** Синхронизация множества заметок с картинками стала радикально быстрее из CLI и browser-sync. Холодный пуш 2000 заметок с 2000 картинок упал с **231.8 с до 8.8 с (~26×)**.
- **Зачем.** Каждая загрузка ассета запускала полный reload всех заметок на сервере, потому что CLI и browser-sync не батчили загрузки так, как уже делал плагин Obsidian, — один забытый флаг (`skipCommit`) превращал 2000 загрузок в 2000 полных reload-ов.
- **Как.** Ничего делать не нужно, кроме обновления до плагина/CLI 0.5.0. Интерактивный плагин Obsidian был не подвержен.

### Стабильность: подписка реального времени могла ронять сервер (`c283963b`)

- **Что.** Гонка в in-process шине событий за подпиской `noteChanges` могла уронить весь сервер, когда подписчик отключался во время сохранения (`send on closed channel`).
- **Зачем.** Пока подписчиков не было, она не стреляла, но новый плагин live-pull подключается и отключается регулярно — это делало баг реальным риском для всех, кто использует подписку.
- **Как.** Ничего делать не нужно; шина теперь использует отдельный done-канал на подписчика и прогнана под нагрузкой с детектором гонок. Также в плагин добавлена команда **Sync now** (палитра команд).

## v0.6.0 — 2026-06-17

### Диаграммы Mermaid

- **Что.** Блок ` ```mermaid ` в заметке рендерится как диаграмма на опубликованной странице — блок-схемы, диаграммы последовательности, круговые, Ганта, классов, состояний, ER и все остальные типы, которые поддерживает Mermaid.
- **Зачем.** Диаграммы пишутся так же, как в Obsidian — блок работает сразу.
- **Как.** Добавьте блок кода с тегом `mermaid` и вставьте синтаксис диаграммы внутрь. Библиотека Mermaid загружается лениво — только на страницах, где есть блок `mermaid`; страницы без диаграмм ничего не платят. Документация: [`docs/en/user/mermaid.md`](../en/user/mermaid.md), [`docs/ru/user/mermaid.md`](./user/mermaid.md).

### Графики из блоков `datachart` (`7cadad3e`, `cb1403f5`)

- **Что.** Блок ` ```datachart ` превращается в интерактивный график на опубликованной странице — на движке Apache ECharts. Данные берутся из четырёх источников: `inline` — строки прямо в блоке; `frontmatter` — файл из vault-а по `[[вики-ссылке]]` в frontmatter; `url` — внешний HTTP-JSON эндпоинт, который trip2g запрашивает на сервере и кеширует; `internal` — данные вашего сайта через SQL (скоро). Ошибки при загрузке URL фиксируются и видны автору сразу при синхронизации, а не только в браузере (`97997bb4`).
- **Зачем.** Публикуйте живые графики так же естественно, как пишете любую заметку в Obsidian. Виджет ECharts загружается лениво — только на страницах с блоком `datachart`.
- **Как.** Добавьте блок с тегом `datachart`, внутри — JSON-объект с ключами `data` и `config`. Объект `config` передаётся прямо в ECharts: работают все типы графиков и опции, которые он поддерживает. Документация: [`docs/en/user/chartdata.md`](../en/user/chartdata.md), [`docs/ru/user/chartdata.md`](./user/chartdata.md).

### MCP Federation — эндпоинт топологии для администраторов и настраиваемый `kb_id` (`4485b6cd`, `5c7492ae`)

- **Что.** Два дополнения к федерации, появившейся в v0.4.1. Новый эндпоинт `GET /_system/federation/admin` (только для администраторов) возвращает полную топологию федерации: все зарегистрированные KB-пиры, их скоупы и статус доступности. Идентификатор `kb_id` вашего инстанса теперь настраивается вручную; если не задан — берётся хост публичного URL.
- **Зачем.** Операторы нескольких федеративных инстансов видят топологию без погружения в базу данных. Явный `kb_id` даёт стабильный, читаемый идентификатор, который остаётся корректным независимо от домена инстанса.
- **Как.** Эндпоинт требует admin API-ключ или сессию. Задайте `kb_id` в конфигурации инстанса, чтобы переопределить значение по умолчанию. Существующие федеративные настройки менять не нужно.

### SSE-подписки на изменения заметок в реальном времени (`854c56b0`)

- **Что.** Новая GraphQL-подписка `noteChanges` передаёт клиентам события upsert и удаления заметок через SSE с опциональной фильтрацией по glob. Каждое событие содержит diff изменённых HTML-селекторов, чтобы клиент мог точечно обновить DOM без перезагрузки страницы.
- **Зачем.** Позволяет строить интерфейсы, которые отражают изменения vault-а в момент, когда они попадают на сервер — редактор в браузере, панель предварительного просмотра, кастомный дашборд.
- **Как.** Подпишитесь на `noteChanges(glob: "posts/**")` через GraphQL SSE-эндпоинт. Поле `changedHtmlSelectors` в каждом событии перечисляет CSS-селекторы, чей рендер изменился — это позволяет обновлять только нужные части страницы.

### Редактор в браузере: переход по wikilink через Ctrl+Click (`a065fea2`)

- **Что.** В редакторе файлов в браузере (появился в v0.5.0) Ctrl+Click (или Cmd+Click на macOS) по wikilink открывает связанную заметку.
- **Зачем.** Повторяет поведение Obsidian и убирает необходимость искать нужный файл вручную.
- **Как.** Откройте редактор, наведите курсор на любую `[[вики-ссылку]]` — курсор меняется на указатель. Ctrl+Click — и связанная заметка открыта.

## v0.5.1 — 2026-05-27

### Секреты вебхуков: зашифрованные данные в теле доставки (`0b72acf2`)

- **Что.** У каждого change-вебхука и cron-вебхука в админке появился раздел **Секреты**. Добавляйте именованные пары ключ-значение (например `auth_token`, `api_key`) — они хранятся зашифрованными и отправляются в каждом запросе доставки в поле `payload.secrets`. Получатель вебхука читает их без дополнительных вызовов API.
- **Зачем.** Cron-вебхуки — основа системы плагинов. Плагин — это веб-сервер (или serverless-функция), который получает payload с временным API-токеном и обрабатывает его, как правило в фоне, а затем патчит хранилище, когда готов. Плагины чаще всего stateless: им некуда безопасно хранить собственные учётные данные. Секреты решают эту проблему — trip2g хранит их зашифрованными и доставляет при каждом вызове, так что плагин остаётся credential-free на своей стороне. Если плагину нужно больше времени, он использует API-токен для асинхронных обновлений; секреты дают ему всё остальное для работы с внешними сервисами.
- **Как.** Откройте Admin → Change Webhooks (или Cron Webhooks) → выберите вебхук → прокрутите до раздела **Секреты**. Введите название и значение, нажмите **Add Secret**. Чтобы обновить значение — введите его в поле строки и нажмите **Save**. Чтобы удалить — нажмите иконку корзины (подтверждение на второй клик). Секреты появляются в теле доставки в виде `{ "secrets": { "auth_token": "...", "api_key": "..." } }`.

## v0.5.0 — 2026-05-26

### Редактор файлов в браузере (для администраторов)

- **Что.** Администратор теперь может отредактировать любую страницу прямо на сайте. Иконка редактора появилась в правом верхнем углу админки и рядом с поиском на каждой странице. Откройте редактор, чтобы просмотреть все загруженные файлы деревом папок, открыть и отредактировать любой и сохранить. Файл можно откатить к прошлой версии.
- **Зачем.** Поправить опечатку или обновить страницу за секунды — без Obsidian и повторной синхронизации.

## v0.4.0 — 2026-05-21

### Мутация updateNotes — атомарный find/replace по заметкам

- **Что.** Новая GraphQL-мутация патчит несколько заметок одной транзакцией через `PathMap` вида `{path → [{find, replace}]}`.
- **Зачем.** Позволяет внешним инструментам, агентам и скриптам согласованно править весь vault без отдельных запросов на каждую заметку. Никаких частичных состояний, если одна замена не прошла.
- **Как.**
  - Документация: [`docs/en/user/update_notes.md`](../en/user/update_notes.md), [`docs/ru/user/update_notes.md`](./user/update_notes.md)
  - Пример: `updateNotes(input: { pathMap: { "notes/post.md": [{ find: "old", replace: "new" }] } })`.
  - End-to-end спецификация: `e2e/updatenotes/*` (см. коммит `test(e2e): add updateNotes e2e spec and demo fixture`).

### Forms admin — обработка отправок формы

- **Что.** Новая мутация `markFormSubmitProcessed` и поля `processed` у submit-ов; админ помечает отправку как обработанную, UI по умолчанию скрывает обработанные.
- **Зачем.** Замыкает работу с формами внутри админки — не нужно дёргать внешние сервисы.
- **Как.**
  - Документация: [`docs/en/user/forms.md`](../en/user/forms.md), [`docs/ru/user/forms.md`](./user/forms.md)
  - Dev-справка: [`docs/dev/forms.md`](../dev/forms.md)
  - Frontmatter `can_submit` / `success_url` задаёт условия отправки и страницу-подтверждение.

### Smoke-render шаблонов — runtime-ошибки Jet видны сразу при загрузке

- **Что.** При загрузке заметок каждый успешно распарсенный Jet-шаблон выполняется на **первых 10 заметках**, которые ссылаются на него через frontmatter `layout:`. Ошибки и паники рендера превращаются в `NoteWarning` на шаблоне.
- **Зачем.** Раньше шаблон, который парсится, но падает на рендере (например, `{{ note.NoSuchField }}`), ломался только при открытии страницы в браузере. Агент, делающий push-notes, об этом не знал. Smoke-render переносит ошибку на этап загрузки — варнинги попадают в тот же канал, что и parse-ошибки, и видны через `pushNotes` / админский список шаблонов без браузера.
- **Как.** Автоматически, без флагов. После синхронизации ищите в варнингах шаблона `smoke render error` / `smoke render panic`. Шаблоны без `View` (parse-ошибка) и без ссылающихся на них заметок пропускаются.

### Отладка шаблонов — `Meta.Debug()` и глобальный `debug()`

- **Что.** В Jet-шаблонах: `{{ Meta.Debug() }}` выводит метаданные заметки; глобальный `{{ debug(<expr>) }}` через reflection печатает тип, значение и набор методов любого выражения.
- **Зачем.** Убирает цикл «угадай, что видит шаблон» при работе с layout-ами и компонентами.
- **Как.**
  - Документация: [`docs/en/user/jet.md`](../en/user/jet.md), [`docs/ru/user/jet.md`](./user/jet.md) (раздел про отладку).
  - Пример: `{{ debug(note.M()) }}` или `{{ debug(note.Title) }}`.

### CLI `renderlayout.py` — рендер шаблона на заметке из терминала

- **Что.** Отдельный скрипт `scripts/renderlayout.py` плюс skill `check_templates` для агента.
- **Зачем.** Дает preview шаблонов и воспроизведение проблем без браузера — удобно в CI и при правке `_layouts/`.
- **Как.**
  - Документация: [`docs/en/user/renderlayout.md`](../en/user/renderlayout.md), [`docs/ru/user/renderlayout.md`](./user/renderlayout.md)
  - Skill: [`docs/skills/check_templates.md`](../skills/check_templates.md)

### Исправления
