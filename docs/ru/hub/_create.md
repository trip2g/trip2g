# Как добавить базу в хаб

Запись хаба — это **KB-заметка**: заметка, чей frontmatter указывает на другую
MCP-совместимую базу (`mcp_federation_kb_url`). После синхронизации хаб может
обращаться к этой базе через `federated_search` и соседние методы. Как устроена
федерация целиком — см. [[ru/user/federation|MCP Federation]].

## 1. Создайте двуязычную пару

Каждая запись — это две заметки, по одной на язык, связанные через `lang_redirect`
(который нужен **только** для языковых альтернатив — это не мульти-диспетчер):

`docs/ru/hub/<name>.md`

```yaml
---
title: "<Название базы>"
free: true
lang: ru
lang_redirect: "[[en/hub/<name>]]"
mcp_federation_kb_url: https://<host>/_system/mcp
mcp_federation_kb_id: <kb_id>
---

Что это за база и когда агенту стоит к ней обращаться.
```

`docs/en/hub/<name>.md`

```yaml
---
title: "<Base name>"
free: true
lang: en
lang_redirect: "[[ru/hub/<name>]]"
---

What the base is and when to use it.
```

**Федеративные поля ставьте ровно на одну заметку** (в этом примере — на одну из
языковых версий). Если `mcp_federation_kb_url` / `mcp_federation_kb_id` будут на
обеих версиях, хаб зарегистрирует один `kb_id` дважды — дублирующийся веерный
поиск и неоднозначная адресация. Вторая языковая версия — просто альтернатива.

| Поле | Обязательно | Назначение |
|------|-------------|------------|
| `mcp_federation_kb_url` | да | Удалённый MCP-эндпоинт. Помечает заметку как KB-заметку. |
| `mcp_federation_kb_id` | нет | Слаг для адресной выборки (`federated_search(kb_id=…)`). По умолчанию — хост из URL. Держите уникальным в пределах хаба. |
| `free: true` | для публичных | Разрешает анонимным MCP-вызовам маршрутизироваться через эту базу. Уберите, чтобы оставить её только для подписчиков/админа. |

> **Совет: насыпьте в текст заметки ключевые слова.** Обычный `search` по хабу ищет
> по контенту заметок, а не по федеративным базам. Перечислите в теле, что лежит в
> базе — темы, технологии, типы задач, характерные термины. Тогда плоский `search`
> сразу выведет эту запись, и агент попадёт к нужной базе ещё до федеративного
> поиска (а оттуда — `federated_search(kb_id=…)`).

## 2. Публичная или приватная база

- **Публичная база** (без аутентификации) — больше ничего не нужно, хаб проксирует
  анонимно.
- **Приватная база / адаптер** (нужен ключ) — добавьте **исходящий федеративный
  секрет** в Админка → Federation: вставьте `kid` + секрет, который дал пир, и
  `kb_url` базы. Тогда хаб подписывает исходящие вызовы. Пока ключ не задан,
  анонимные запросы к этой базе возвращают пустой результат.

## 3. Добавьте в индекс хаба

Добавьте строку в оба индекса:

- `docs/ru/hub/_index.md`: `- [[ru/hub/<name>|<Название базы>]]`
- `docs/en/hub/_index.md`: `- [[en/hub/<name>|<Base name>]]`

## 4. Синхронизация

Синхронизируйте vault. Проверьте адресным вызовом:
`federated_search(query: "…", kb_id: "<kb_id>")`, и убедитесь, что запись видна в
веерном `federated_search` (без `kb_id`).
