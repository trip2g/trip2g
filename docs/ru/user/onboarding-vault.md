Стартовый архив — это готовое хранилище Obsidian, которое вы скачиваете со своего инстанса trip2g. Плагин синхронизации уже установлен и подключён к **вашему** инстансу: адрес сайта и свежий API-ключ вписаны в настройки. Распакуйте архив, откройте в Obsidian, нажмите синхронизацию — и заметки окажутся на сайте. Ничего устанавливать и настраивать не нужно.

На этой странице разобрано, что лежит внутри архива, как синхронизировать без Obsidian и как защитить API-ключ из архива.

### Где взять архив

Свежий инстанс встречает администратора страницей с кнопкой «Скачать архив». Каждое скачивание создаёт новый API-ключ и вписывает его в архив.

![[./img/onboarding-download.jpg]]

1. **Скачать архив** — ссылка на скачивание. Она видна только когда вы вошли как администратор.
2. **Шестерёнка** — вход в админ-панель. Шестерёнка появляется в верхней панели после входа под администратором; если её нет — вы не авторизованы.

Полный разбор первой синхронизации — в статье [[Начало работы]].

### Что лежит внутри архива

Архив — это обычное хранилище Obsidian плюс несколько заранее заполненных конфигов:

| Путь | Что это |
|------|---------|
| `_index.md` | Главная страница сайта. Отредактируйте и синхронизируйте — изменится титульная страница. |
| `.obsidian/plugins/trip2g/` | Плагин синхронизации и его инструменты (см. ниже). |
| `.mcp.json`, `codex.json` | Конфиги MCP-серверов для AI-агентов (Claude Code, Codex), уже заполнены адресом и ключом вашего инстанса. |
| `antigravity-mcp-config.json` | Конфиг MCP для Antigravity — скопируйте его в `~/.gemini/antigravity/mcp_config.json`. |
| `AGENTS.md` | Инструкция, которую читает AI-агент, чтобы искать и публиковать ваши заметки. |

Конфиги MCP и `AGENTS.md` позволяют AI-агенту искать по опубликованным заметкам и, при включённой настройке, управлять сайтом. Смотрите [[agent-memory]].

### Внутри папки плагина

В `.obsidian/plugins/trip2g/` лежит плагин синхронизации и два файла, о которых стоит знать:

- `trip2g-sync.mjs` — самостоятельный Node-скрипт, который синхронизирует хранилище из терминала, без запуска Obsidian.
- `data.json` — настройки плагина, включая ваш API-ключ. Относитесь к нему как к паролю (см. предупреждение ниже).

### Синхронизация без Obsidian

`trip2g-sync.mjs` выполняет ту же синхронизацию, что и кнопка плагина, но из командной строки. Используйте его для автоматизации, headless-серверов и CI/CD.

Запускайте из корня хранилища:

```bash
node .obsidian/plugins/trip2g/trip2g-sync.mjs --folder .
```

`--folder` — папка для синхронизации, `.` означает всё хранилище. Скрипт сам читает `apiUrl` и `apiKey` из `.obsidian/plugins/trip2g/data.json`, поэтому внутри скачанного хранилища флаги `--api-key` и `--api-url` не нужны.

Два флага закрывают большинство задач:

```bash
# Показать, что изменится, без внесения изменений
node .obsidian/plugins/trip2g/trip2g-sync.mjs --folder . --dry-run

# Двухсторонняя синхронизация: ещё и скачать изменения с сервера
node .obsidian/plugins/trip2g/trip2g-sync.mjs --folder . --two-way
```

В CI передавайте ключ через переменные окружения, а не через `data.json`:

```bash
export TRIP2G_API_KEY=ваш_api_ключ
export TRIP2G_ENDPOINT=https://yoursite.com/_system/graphql
node trip2g-sync.mjs --folder ./docs
```

Запустите скрипт с `--help`, чтобы увидеть все флаги. Полный разбор CI/CD — GitHub Actions, мульти-репозитории через `--meta`, режимы конфликтов — в статье [[cli]].

### Берегите API-ключ в data.json

> **Важно: `data.json` содержит рабочий API-ключ с полным доступом на запись в ваше хранилище.** Любой, у кого есть этот файл, может перезаписать или заменить **весь** ваш опубликованный контент. Относитесь к нему как к паролю.

Конкретно:

- Не коммитьте `data.json` в публичный репозиторий.
- Не выкладывайте скачанный архив в открытый доступ — в нём лежит ключ.
- Не вставляйте `data.json` и его содержимое в чаты, задачи и pastebin.
- В CI/CD храните ключ в секрете CI и передавайте через `TRIP2G_API_KEY`. Не коммитьте `data.json`.

Если ключ утёк, отзовите его в админке, раздел «API ключи», и скачайте новый архив.

### Сделайте бэкап перед синхронизацией

trip2g ничего не удаляет на сервере сам по себе. Автоматической сборки мусора сейчас нет — сборщик мусора запланирован, но пока не сделан. Заметки, удалённые локально, на сервере скрываются, а не стираются, поэтому на стороне сервера данные почти никогда не теряются сами.

Настоящий риск — на стороне синхронизации. Неверный или задвоенный API-ключ в `data.json` или несовпадающий конфиг могут направить плагин на чужое хранилище и перезаписать ваш контент не теми заметками. Две привычки защитят вас:

- Держите бэкап заметок (Git-репозиторий или копию папки) перед большими синхронизациями.
- Перед синхронизацией хранилища, которое вы только что не скачали, проверьте `data.json` — убедитесь, что `apiUrl` указывает на нужный инстанс.

Общая стратегия резервного копирования — в статье [[backup|Бэкапы]].
