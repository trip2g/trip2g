# Как писать страницы документации

## Процесс

1. **Черновик** — напишите текст как есть, не думая о стиле
2. **Редактура** — вызовите `/bmad:custom:agents:maximilyahov` для проверки и правки
3. **Навигация** — добавьте страницу в `_sidebar.md` и `_index.md`
4. **Проверка** — пройдите по опроснику ниже

## Опросник

Перед публикацией убедитесь, что текст отвечает на эти вопросы:

### Зачем это нужно?
- [ ] Какую проблему решает эта функция?
- [ ] Что будет, если её не использовать?

### Что получит пользователь?
- [ ] Какая польза для владельца сайта?
- [ ] Какая польза для его читателей?
- [ ] Сколько усилий потребуется для настройки?

### Кому это нужно?
- [ ] Описан сценарий использования?
- [ ] Понятно, подходит ли функция конкретному читателю?

### Как это работает?
- [ ] Объяснён принцип работы простыми словами?
- [ ] Нет скрытых ограничений в конце текста?
- [ ] Важные условия описаны до инструкции, а не после?

### Как настроить?
- [ ] Есть пошаговая инструкция?
- [ ] Каждый шаг — одно действие?
- [ ] Указаны конкретные названия кнопок и разделов?

### Что может пойти не так?
- [ ] Описаны частые ошибки?
- [ ] Есть способы их решить?

## Добавление в навигацию

### _sidebar.md

Добавьте ссылку в подходящий раздел:

```markdown
- [Название страницы](/docs/slug)
```

Разделы:
- **Основы** — базовые функции для всех
- **Telegram** — публикация в Telegram
- **AI и интеграции** — MCP, боты, автоматизации
- **Кастомизация** — шаблоны, Jet, layouts
- **Дополнительно** — SEO, self-hosted, бекапы, OAuth

### _index.md

Добавьте ссылку с описанием в одну строку:

```markdown
[[slug|Название страницы]]
Краткое описание — что делает и зачем нужно.
```

Описание должно:
- Уместиться в одно предложение
- Объяснять пользу, а не функцию
- Начинаться с глагола или существительного
