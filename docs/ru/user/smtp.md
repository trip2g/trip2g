Чтобы войти, trip2g присылает одноразовый код на почту. Нет работающей отправки писем — нет кода — не войти. Значит, self-hosted-инстансу нужен способ отправлять почту. Практичный ответ — готовый сервис транзакционной почты: выберите из списка ниже, впишите его SMTP-данные в конфиг, и всё.

Два способа вообще обойтись без почты, прежде чем выбирать провайдера:

- **Вход через Google или GitHub (OAuth).** Ни почты, ни SMTP, ни аккаунта у провайдера. Если вход через OAuth покрывает всех, кому нужен доступ, эта страница вам не нужна.
- **Не поднимайте свой почтовый сервер.** На свежем VPS исходящий порт `25` почти всегда заблокирован хостером, а письма с нового IP попадают в спам или отклоняются. Наработать репутацию — это недели. У готового сервиса уже прогретые IP и правильная DNS-репутация — поэтому это практичный путь.

Полное руководство по self-hosting — в [[selfhosted]]; здесь только про почту.

### Какой провайдер выбрать

Все они дают SMTP-логин и пароль, которые вы вставляете прямо в trip2g. Отсортировано по пользе для небольшого self-host: сначала щедрые бессрочно-бесплатные тарифы с обычным SMTP, в конце — только-триал и pay-as-you-go.

### Подключение к trip2g

trip2g отправляет почту по обычному SMTP. Нужные настройки (переменная окружения / CLI-флаг):

| Переменная | Флаг | По умолчанию | Что значит |
|---|---|---|---|
| `SMTP_HOST` | `-smtp-host` | *(пусто = только лог)* | SMTP-сервер провайдера. Пусто — письма не отправляются. |
| `SMTP_PORT` | `-smtp-port` | `587` | SMTP-порт. `587` для STARTTLS — обычный выбор. |
| `SMTP_USER` | `-smtp-user` | *(пусто)* | SMTP-логин от провайдера. |
| `SMTP_PASS` | `-smtp-pass` | *(пусто)* | SMTP-пароль / API-ключ от провайдера. |
| `SMTP_STARTTLS` | `-smtp-starttls` | `true` | Использовать STARTTLS. Для порта `587` оставьте `true`. |
| `MAIL_FROM` | `-mail-from` | `no-reply@example.com` | Адрес отправителя. **Обязан** быть на домене, подтверждённом у провайдера, иначе письма отклоняются. |

Пример блока `/etc/trip2g.env` на SMTP-релее Brevo:

```dotenv
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=your-login@example.com
SMTP_PASS=<SMTP-ключ Brevo>
SMTP_STARTTLS=true
MAIL_FROM=no-reply@your-verified-domain.com
```

Каждый провайдер даёт те же три значения — host, user, pass. У Resend это `smtp.resend.com`, пользователь `resend`, пароль — ваш API-ключ. У Mailjet — `in-v3.mailjet.com` с парой API-ключ/секрет. Точный host смотрите на странице настройки SMTP у провайдера.

`MAIL_FROM` — типичная ловушка: адрес должен быть на домене, который вы добавили и подтвердили (его DNS-записи) у провайдера. Неподтверждённый домен-отправитель отклоняется — то есть почта заработает только когда подтверждение станет зелёным.

**Легаси-ярлык для Resend.** На старых инстансах почта настраивалась одним `RESEND_API_KEY`. Он ещё работает: если `SMTP_PASS` не задан, но есть `RESEND_API_KEY`, trip2g автоматически подставляет его в SMTP-шлюз Resend (и пишет предупреждение об устаревании). Для нового ставьте переменные `SMTP_*`.

**Почты ещё нет?** trip2g работает и без SMTP — просто пропускает письма со входом. Чтобы загрузить самый первый вход, поставьте `LOG_SIGN_IN_CODES=true`, перезапустите, инициируйте вход и прочитайте код из лога сервера (`journalctl -u trip2g`). Снимите флаг, как только войдёте, — он печатает коды в открытом виде.

### Что выбрать

- **Проще всего:** **Brevo** (300/день бессрочно, обычный SMTP) или **Resend** (родной для trip2g, чистая настройка). Оба бесплатны и достаточны для личного инстанса или небольшой команды.
- **Максимум объёма / дешевле всего:** **Amazon SES** (~$0,10/1 000) или **Zoho ZeptoMail** (~$2,50/10 000). Настройки больше, счета копеечные.
- **Совсем без почты:** используйте вход через **Google/GitHub (OAuth)** и пропустите эту страницу.

Начните с бесплатного варианта, сначала проверьте, что письмо со входом доходит, и переходите на платный тариф, только когда реально упрётесь в дневной лимит.
