Чтобы войти, trip2g присылает одноразовый код на почту. Нет работающей отправки писем — нет кода — не войти. Значит, self-hosted-инстансу нужен способ отправлять почту. trip2g говорит по обычному SMTP, так что подойдёт любой сервис транзакционной почты: выберите из списка ниже, впишите его SMTP-данные в конфиг, и всё.

Два способа вообще обойтись без почты, прежде чем выбирать провайдера:

- **Вход через Google или GitHub (OAuth).** Ни почты, ни SMTP, ни аккаунта у провайдера. Если вход через OAuth покрывает всех, кому нужен доступ, эта страница вам не нужна.
- **Не поднимайте свой почтовый сервер.** Это худший вариант — подробности ниже.

Полное руководство по self-hosting — в [[selfhosted]]; здесь только про почту.

### Почему не стоит поднимать свой почтовый сервер

Теоретически возможно, на практике — худший вариант. Не тратьте на это день. Полевой тест на свежем VPS Hetzner:

- **Исходящий порт 25 заблокирован по умолчанию.** `nc gmail-smtp-in.l.google.com 25` просто отваливается по таймауту, а `nc <хост-релея> 587` подключается мгновенно. Большинство хостеров (Hetzner и крупные облака) блокируют исходящий `25` для борьбы со спамом.
- **Локальный MTA не спасает.** Ставите Postfix — и письмо навсегда зависает в статусе `deferred`: оно не может достучаться до исходящего порта `25`, поэтому не доставляется. Ни в инбокс, ни даже в спам. Просто копится в очереди.
- **Разблокировать `25` — это только начало настоящей борьбы.** Даже с открытым портом дальше нужно выиграть rDNS/PTR, SPF, DKIM, DMARC и с нуля наработать репутацию холодного IP. Недели работы, и одна ошибка отправляет вас в блок-лист.

Вывод: отправляйте через готовый релей на порту `587`. Не поднимайте свой исходящий MTA. Дальше страница — про то, как выбрать этот релей.

### Какой провайдер выбрать

Все они дают SMTP-логин и пароль, которые вы вставляете прямо в trip2g. Отсортировано по пользе для небольшого self-host: сначала щедрые бессрочно-бесплатные тарифы с обычным SMTP, в конце — только-триал и pay-as-you-go.

Самый большой бесплатный тариф — не автоматически лучший отправитель: доставляемость и репутация различаются. Колонка **Репутация** показывает, как каждый *принято оценивать* для транзакционной почты; это грубый сигнал, не рейтинг, и настройка вашего домена (подтверждённый отправитель, SPF, DKIM) значит не меньше.

Цифры актуальны на середину 2026. Бесплатные тарифы часто меняются — **сверьтесь со страницей тарифов провайдера, прежде чем полагаться на число.**

### Подключение к trip2g

trip2g отправляет почту по обычному SMTP. Нужные настройки (переменная окружения / CLI-флаг):

| Переменная | Флаг | По умолчанию | Что значит |
|---|---|---|---|
| `SMTP_HOST` | `-smtp-host` | *(пусто = только лог)* | SMTP-сервер провайдера. Пусто — письма не отправляются. |
| `SMTP_PORT` | `-smtp-port` | `587` | SMTP-порт. `587` для STARTTLS — обычный выбор. |
| `SMTP_USER` | `-smtp-user` | *(пусто)* | SMTP-логин от провайдера. |
| `SMTP_PASS` | `-smtp-pass` | *(пусто)* | SMTP-пароль / API-ключ от провайдера. |
| `SMTP_STARTTLS` | `-smtp-starttls` | `true` | Использовать STARTTLS. Для порта `587` оставьте `true`. |
| `MAIL_FROM` | `-mail-from` | `no-reply@example.com` | Адрес отправителя. **Обязан** быть на домене, подтверждённом у провайдера, иначе письма отклоняются. |

Пример блока `/etc/trip2g.env` на SMTP-релее Brevo:

```dotenv
SMTP_HOST=smtp-relay.brevo.com
SMTP_PORT=587
SMTP_USER=your-login@example.com
SMTP_PASS=<SMTP-ключ Brevo>
SMTP_STARTTLS=true
MAIL_FROM=no-reply@your-verified-domain.com
```

Каждый провайдер даёт те же три значения — host, user, pass. У Resend это `smtp.resend.com`, пользователь `resend`, пароль — ваш API-ключ. У Mailjet — `in-v3.mailjet.com` с парой API-ключ/секрет. Точный host смотрите на странице настройки SMTP у провайдера.

`MAIL_FROM` — типичная ловушка: адрес должен быть на домене, который вы добавили и подтвердили (его DNS-записи) у провайдера. Неподтверждённый домен-отправитель отклоняется — то есть почта заработает только когда подтверждение станет зелёным.

**Почты ещё нет?** trip2g работает и без SMTP — просто пропускает письма со входом. Чтобы загрузить самый первый вход, поставьте `LOG_SIGN_IN_CODES=true`, перезапустите, инициируйте вход и прочитайте код из лога сервера (`journalctl -u trip2g`). Снимите флаг, как только войдёте, — он печатает коды в открытом виде.

### Что выбрать

- **Проще всего бесплатно:** **Brevo** (300/день бессрочно, обычный SMTP), **Resend** или **Mailjet**. Все бесплатны и достаточны для личного инстанса или небольшой команды.
- **Лучшая репутация доставляемости:** **Postmark** (эталон для транзакционной почты, но платный) или **Amazon SES** — стоит того, если недошедший код для вас реальная проблема.
- **Максимум объёма / дешевле всего:** **Amazon SES** (~$0,10/1 000) или **Zoho ZeptoMail** (~$2,50/10 000). Настройки больше, счета копеечные.
- **Совсем без почты:** используйте вход через **Google/GitHub (OAuth)** и пропустите эту страницу.

Помните: самый большой бесплатный тариф — не автоматически лучший отправитель. Начните с бесплатного варианта, сначала проверьте, что письмо со входом реально доходит, и переходите на платный тариф, только когда упрётесь в дневной лимит или понадобится более надёжная доставляемость.
