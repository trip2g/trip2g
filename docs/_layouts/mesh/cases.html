topology · solo
[01] solo

One person, many bases

Role
Researcher or learner with knowledge scattered across Obsidian, books, courses, saved articles.
Setup
One hub. Each book, course, project = a separate base. Add when you start, pause when you finish.
Outcome
One question to your agent — answers from everything you've ever read, with sources.
topology · friends
[02] friends

Private network, 3–5 peers

Role
A small trusted circle — co-readers, study partners, building together.
Setup
Each person runs their own hub. All hubs connect to all hubs. Per-base trust.
Outcome
One agent question reaches the union of everyone's knowledge — no SaaS in the middle.
topology · company
[03] company internal

Star: company + employees

Role
Org with shared docs + each employee's working notes. Roles, scopes, retention.
Setup
One central hub holds canon. Each employee runs (or rents) a personal hub that peers with the center.
Outcome
Onboarding answers, project history, tribal knowledge — queryable, but per-vault access stays granular.
topology · b2b
[04] b2b mesh

Two companies, one bridge

Role
Partner orgs that need to share a slice — research, supply chain, joint projects.
Setup
Each company keeps its star intact. The two central hubs peer with scoped, audited access.
Outcome
Shared knowledge without merging systems, exporting data, or signing into a third party.

topology · solo
[01] solo

Один человек, много баз

Роль
Исследователь или учащийся — знания разбросаны по Obsidian, книгам, курсам, сохранённым статьям.
Настройка
Один хаб. Каждая книга, курс, проект — отдельная база. Добавь когда начинаешь, поставь на паузу когда заканчиваешь.
Результат
Один вопрос агенту — ответы из всего что вы когда-либо читали, с источниками.
topology · friends
[02] friends

Приватная сеть, 3–5 участников

Роль
Небольшой доверенный круг — совместные читатели, напарники по учёбе, командная работа.
Настройка
Каждый запускает свой хаб. Все хабы связаны друг с другом. Доступ настраивается на уровне базы.
Результат
Один вопрос агенту — ответ из объединённых знаний всей группы, без SaaS посередине.
topology · company
[03] company internal

Звезда: компания + сотрудники

Роль
Организация с общими документами и личными рабочими заметками сотрудников. Роли, области доступа, хранение.
Настройка
Один центральный hub хранит канонические данные. Каждый сотрудник запускает (или арендует) личный hub, связанный с центром.
Результат
Онбординг, история проектов, неформальные знания — всё доступно для запросов, но доступ к каждому vault остаётся гранулярным.
topology · b2b
[04] b2b mesh

Две компании, один мост

Роль
Партнёрские организации, которым нужно обменяться частью данных — исследования, цепочки поставок, совместные проекты.
Настройка
Каждая компания сохраняет свою звезду. Два центральных hub'а связаны через ограниченный, аудируемый доступ.
Результат
Общие знания без слияния систем, экспорта данных и входа в сторонний сервис.
