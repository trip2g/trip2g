# How to Write Clear Text

Rules for writing that readers actually understand. Use as a checklist when reviewing any content.

---

## The Minto Pyramid Principle

Barbara Minto's core insight: readers understand you fastest when you lead with the answer, then explain why.

**Structure every piece of writing as a pyramid:**

```
        [Main Point]
       /            \
 [Argument 1]  [Argument 2]  [Argument 3]
   /     \       /     \       /     \
[detail][detail][detail][detail][detail][detail]
```

- The top answers the reader's question before they have to ask it
- The middle groups 3–5 supporting arguments
- The bottom provides evidence, examples, and data

**The SCQA opening** — use to frame any document:

1. **Situation** — what the reader already knows and accepts as true
2. **Complication** — what has changed or gone wrong
3. **Question** — the question the complication naturally raises
4. **Answer** — your main point (this becomes the top of your pyramid)

---

## Structure Rules

1. **Lead with the answer** — state your main point in the first sentence; explain why afterward
2. **One idea per level** — every heading, paragraph, and sentence carries exactly one idea
3. **Group before you list** — ideas in a group must belong to the same category (MECE: mutually exclusive, collectively exhaustive)
4. **Top summarizes the bottom** — every heading must be a true summary of everything below it, not just a label
5. **Three to five points per group** — if you have more, split into subgroups; if you have one, merge it up
6. **Deductive order for arguments** — when ideas form a logical chain (A → B → C); use for recommendations
7. **Inductive order for lists** — when ideas are parallel examples of the same thing; use for analysis

---

## Paragraph Rules

8. **First sentence = topic sentence** — it states the paragraph's single idea; the rest supports it
9. **Read first sentences only** — they should form a complete argument on their own
10. **One paragraph, one point** — never carry a thought across paragraphs
11. **Last sentence = bridge** — close by setting up the next paragraph
12. **Keep paragraphs autonomous** — a paragraph lifted out of context should still make sense

---

## Sentence Rules

13. **Subject → verb → object** — keep this order; readers process it fastest
14. **Actor in the subject** — the person doing the thing goes first, not buried in a phrase
15. **Action in the verb** — use "we built" not "the implementation was carried out"
16. **One idea, one sentence** — split anything with more than one main clause
17. **Conclusion before reason** — write "we recommend X because Y", not "because Y, we recommend X"

---

## Word Rules

18. **Cut filler** — remove words that carry no meaning ("basically", "in order to", "it should be noted")
19. **No vague quantities** — replace "some", "certain", "a number of" with specifics
20. **No imposed judgments** — don't write "importantly" or "significantly"; let the fact carry its own weight
21. **Avoid parentheses** — if the content matters, put it in the sentence; if it doesn't, cut it
22. **Use concrete nouns** — "the finance team reviewed the budget" beats "a review was conducted"

---

## Clarity Rules

23. **Abstract + example + counter-example** — the strongest way to make any idea stick
24. **Write for the reader's question** — before writing, ask "what question is the reader trying to answer?"
25. **Never bury the lead** — if the reader has to reach the third paragraph to understand what the text is about, rewrite
26. **Diagnose before prescribing** — describe the problem clearly before offering a solution
27. **Scannable by design** — a reader skimming only headings and first sentences should get the full message
