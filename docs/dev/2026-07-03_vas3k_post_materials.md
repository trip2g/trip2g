# Материалы для поста в Вастрик.Клубе про trip2g

Дата: 2026-07-03. **Это НЕ пост.** Это сырьё: факты, углы, структура, правила. Текст пишет человек, своими словами, по-русски. Причина ниже, в разделе 7 — клуб прямо запрещает AI-генерированные посты и детектит AI-прозу нюхом.

## 1. Портрет клуба

- **Первая ценность клуба — живой человеческий опыт.** Официальная AI-полиси ([vas3k.club/post/ai_policy](https://vas3k.club/post/ai_policy/), теперь правило №12 в [правилах](https://vas3k.club/docs/about/)): посты, целиком или по большей части сгенерированные ИИ, запрещены. Отдельно запрещён «AI-полиш» своего текста: «ИИ-обработка ВСЕГДА делает текст хуже». Несовершенный живой голос ценится выше гладкого робота.
- **Что при этом МОЖНО по той же полиси:** ИИ как инструмент подготовки — ресёрч, факт-чекинг, план структуры, вычитка. При сомнениях — дисклеймер в начале поста; прозрачность снимает большинство конфликтов. Этот пак — ровно тот разрешённый случай: подготовка, не текст.
- **Самопиар разрешён, но в форме «дай ценность взамен»** ([правила](https://vas3k.club/docs/about/)): «Прося что-то у Клуба, давайте ему взамен». Голая реклама стартапа и рекрутинг — нет; личная история «как я это строил, что узнал, где облажался» — да. Для чистого «покажи проект» есть регулярные треды «Самопиар — покажи свой пет-проджект» (например [март 2023](https://vas3k.club/thread/18610/), [июль 2024](https://vas3k.club/thread/24784/), [октябрь 2024](https://vas3k.club/thread/25885/)) — там формат: ссылка, как появился, какую проблему решает, что нового с прошлого раза.
- **Тон:** на «ты», разговорный, можно материться, нельзя быть слишком серьёзным. Реальное имя, никакой анонимности, вежливость обязательна, «это говно» без аргументов банят ([about](https://vas3k.club/docs/about/)).
- **Анти-хайп в ДНК.** Вастрик создал клуб как ответ на «попсение» — погоню за охватами и спонсорами ([зачем клуб](https://vas3k.blog/notes/the_club/)). Маркетинговый язык здесь — красная тряпка. Никаких платных манипуляций и «нативных интеграций», даже у администрации.
- **К AI-теме по существу — нормально.** В клубе живут треды вроде «Кроме хайпа, какие реальные проблемы вы автоматизировали с помощью LLM?» ([тред](https://vas3k.club/thread/25726/)) и «Для чего вы используете локальный AI?» ([тред](https://vas3k.club/thread/28609/)). Уважают: измерения, личный опыт, скепсис, локальное/self-hosted. Роняют: евангелизм, «AI изменит всё», продуктовый питч в AI-обёртке.
- **Эталон регистра — сам Вастрик** ([vas3k.blog](https://vas3k.blog/), [«А как делать блог?»](https://vas3k.blog/notes/how_to_blog/)): инженерная глубина + самоирония + честность про провалы + конкретика вместо оценок. «Инжой» — писать потому что в кайф, а не для конверсии.
- **Как подать проект, чтобы не словить аллергию:** это пост про *опыт постройки*, а не про продукт. AI-часть подаётся как измеренный скепсис, а не как фича. Провалы называются раньше, чем достижения. В конце — вопрос клубу, а не CTA. И дисклеймер, что заготовку фактов помогал собирать агент, — по AI-полиси это честно и достаточно.

## 2. Угол (позиционирование)

**Рекомендуемый угол: ремесленный, не AI-шный.**

Вести с ремесла и личной боли: «мой Obsidian-вольт — источник правды всего, что я публикую; надоел цикл export→build→deploy; построил self-hosted сервер, куда вольт синкается в обе стороны». Дальше инженерные решения, которые клубу интересны сами по себе: Go-монолит одним бинарём, SQLite вместо Postgres (и почему), git-зеркало базы (git clone своего вольта по Smart HTTP), федерация хабов с HMAC и счётчиком глубины как TTL у IP.

**AI/MCP-часть — во второй половине, как честно измеренный скепсис**, а не как продающая фича: «агенты жрут токены; я померил на живом эндпоинте, что чтение одной секции вместо целой заметки даёт медиану 15×; и тут же честно: детерминированный выбор секции провалился на 8 из 9 запросов — попасть в *нужную* секцию оказалось нерешённой половиной задачи». Скептик такое уважает: это измерение с провалом внутри, а не питч.

Почему так: (а) клуб не против AI-темы, клуб против AI-хайпа и AI-прозы; (б) «сделал сам, вот кишки, вот где облажался» — ровно формат, который там взлетает; (в) бенчмарк воспроизводим 50-строчным скриптом без зависимостей — кто-то в комментах его запустит, и это лучший исход.

Альтернатива-минимум: если лонгрид не хочется — короткий заход в очередной тред «Самопиар» по их формату (ссылка + как появился + что решает + апдейты).

## 3. Фактура (сырьё для текста)

Всё проверено по README (колонка статуса = источник правды) и docs/en/user/token-economy-bench.md. Ветку и планы НЕ выдавать за готовое.

**Что это.** Self-hosted сервер на Go + SQLite, MIT. Obsidian-вольт синкается two-way: правишь заметку локально — страница живая примерно через секунду; правишь через сайт/API — изменение возвращается в вольт. Те же markdown-заметки сервер отдаёт трижды: сайт для людей, MCP-эндпоинт для агентов, посты в Telegram-канал. Каждая правка — версия в БД + коммит в git-зеркало; весь вольт можно `git clone` по Smart HTTP.

**Бенчмарк (с обязательными оговорками).**
- Чтение одной секции (search возвращает `toc_path` прямо на заголовок) vs дамп целой заметки: **медиана 15.4×, максимум 37.2×** (страница templates: 7668 токенов целиком vs 206 секцией), минимум 3.7× (заметка и так короткая). 8 реальных вопросов к живой документации, публичный эндпоинт, скрипт ~50 строк на чистом stdlib Python — любой может перепроверить.
- Оговорка 1: baseline — наивный дамп целой заметки, НЕ тюненый RAG-пайплайн; с хорошим chunk-retrieval разрыв меньше.
- Оговорка 2: токенайзер простой (`\w+|[^\w\s]`), не клодовский; абсолютные числа приблизительные, но обе руки меряются одной линейкой, поэтому *отношение* честное.
- Дополнительное измерение: наивный `grep` по локальным .md + чтение файлов — ~4600 токенов, т.е. 23× дороже секции и даже 1.7× дороже целой заметки через MCP: grep находит файлы, а не границы секций. Оговорка: наивный grep, один прогон, en+ru дубли; умелый человек с `grep -n` сузил бы разрыв.
- **Главный честный провал: экономия токенов — лёгкая половина. Тяжёлая — попасть в нужную секцию. Детерминированный выбор секции провалился на 8 из 9 запросов.** Из шести проверяемых вопросов секция содержала подсвеченные термины ответа в четырёх; промахи — стоп-слово и соседняя секция. Именно поэтому search отдаёт точный путь в дереве, а не «где-то в этом файле», и есть `expand` для навигации по оглавлению.

**Инженерные решения и почему (для «кишок»).**
- SQLite вместо Postgres: один процесс, один файл, нечего администрировать; Litestream стримит бэкап; read/write разнесены в приложении. Read-реплики (LiteFS) есть, но на ветке `feat/read-replica`, не в main.
- Go-монолит одним бинарём: `docker compose up` — вся установка; search, рендер, MCP, Telegram, git — один процесс над одним файлом БД. FastHTTP, gqlgen; GraphQL-подписки по SSE поверх fasthttp.
- Федерация: один MCP-запрос веером по peer-хабам; HMAC-подписанные короткоживущие токены, per-hop счётчик глубины (`X-MCP-Federation-Depth`) против `max_depth` — циклы ограничены как TTL у IP-пакета.
- Git-зеркало: БД каноническая, git-дерево материализуется по требованию (`gitapi`); push применяется обратно в заметки. История правок — читаемые диффы, не бинарный блоб.
- Фронтенд на $mol — самая спорная зависимость репозитория; выбран за крошечные бандлы; порог входа для контрибьюторов реальный.
- Полнотекст (bleve) работает полностью офлайн; markdown — Goldmark с wikilinks и frontmatter.

**Провалы и ограничения (называть самому, раньше комментаторов).**
- Выбор секции 8/9 — см. выше; нерешённая половина.
- Agent-runtime (LLM-цикл `agentruntime`, fleet «роль-как-заметка») — на ветке `feat/agent-runtime`, НЕ в main. В README таблица честно помечает shipped/branch/planned.
- Нет graph view — кому это любимая фича Obsidian, тому лучше Publish или Quartz (в доках это прямо сказано).
- Семантический поиск требует внешний embeddings-эндпоинт (любой OpenAI-совместимый, можно локальный); без него — только полнотекст.
- Sync-плагин пока side-loaded, не в каталоге community plugins.
- Молодой проект, маленькое комьюнити, pet-project одного человека со всеми вытекающими.

## 4. Личные крючки

Вопросы, на которые ответить своими словами (пустые — специально; за тебя тут отвечать нельзя, это и есть «живой опыт», который клуб ценит):

1. Что конкретно бесило в существующих решениях (Obsidian Publish, Quartz, статические генераторы) до того, как начал строить? Какой момент стал последней каплей?
2. Зачем тебе лично это: что публикуешь, кому, как выглядит твой ежедневный цикл «заметка → сайт»?
3. Что удивило по дороге? (Кандидаты из истории проекта: что grep для агента оказался дороже целой заметки через MCP; что экономия токенов тривиальна, а попадание в секцию — нет; любой прод-инцидент — GC death-spiral, забитый диск при ребилде git-зеркала...)
4. На чём облажался и что бы сделал иначе? (Кандидаты: выбор $mol и цена входа для других; data-loss с live-pull; недосайзнутая VM, на которой всё живёт.)
5. Почему такие «немодные» решения — SQLite, монолит, свой фронтенд-фреймворк? Что отвечаешь на «почему не Postgres/Next.js»?
6. Как сам относишься к AI-хайпу? Один честный абзац скепсиса от первого лица — он и задаст тон всей второй половине.

## 5. Структура поста (скелет, не текст)

1. **Личная боль** — свой вольт, свой цикл публикации, что бесило (крючок 1-2).
2. **Что построил** — два-три абзаца: two-way sync, один бинарь на SQLite, git-зеркало. Кишки, а не фичи.
3. **Немодные решения и почему** — SQLite/монолит/$mol (крючок 5). Это самая «клубная» часть.
4. **Одно честное измерение** — бенчмарк с обеими оговорками (baseline, токенайзер) и скриптом.
5. **Что НЕ получилось** — 8/9, ветки не в main, нет graph view, свой AI-скепсис (крючки 4, 6).
6. **Вопрос клубу** — не CTA. Например: «как бы вы решали попадание в нужную секцию?» или «кто как публикует свой вольт — что я упустил?».

Порядок и склейки — на твой вкус; это каркас, чтобы ничего не забыть, а не план, которому обязан следовать.

## 6. Do / Don't

**Don't:**
- НЕ постить AI-текст и НЕ прогонять свой текст через AI «для гладкости» — прямое нарушение [AI-полиси](https://vas3k.club/post/ai_policy/), и клуб такое чует.
- НЕ маркетинговый язык: никаких «революционный», «уникальный», «переосмысляет», «мощный». Существительные и числа вместо прилагательных.
- НЕ прятать провалы и НЕ выдавать ветки/планы за готовое (README-таблица статусов — источник правды).
- НЕ вести с AI: «MCP memory для агентов» первым абзацем — гарантированная аллергия.
- НЕ оформлять как рекламу: без лендинг-скриншотов на пол-экрана, без CTA «попробуйте бесплатно», ссылки на репо/доки — в конце, по делу.
- НЕ иллюстрировать AI-картинками — полиси называет это сигналом низких усилий.
- НЕ спорить в комментах защитно; «справедливо, это реальное ограничение» стоит дороже любого контраргумента.

**Do:**
- Писать самому, на «ты», со своим голосом, с самоиронией; несовершенно — нормально, это фича.
- Признать честно: pet-project одного человека, молодой, с оговорками.
- Конкретные числа с оговорками: 15× медиана, 37× максимум, 3.7× минимум, 8/9 провал, 7668 vs 206 токенов.
- Дать скрипт — воспроизводимость это самый сильный аргумент для скептиков.
- Один абзац личного AI-скепсиса от первого лица.
- Короткий дисклеймер про использование AI при подготовке фактуры (по полиси прозрачность снимает вопросы).
- Быть в комментах первые часы, отвечать по существу, соглашаться с валидной критикой.
- Проверить перед постом: скрипт `te_check.py` против прода работает (кто-то запустит).

## 7. Анти-AI-текст: предупреждение

Клуб запрещает AI-генерированные посты правилом и детектит AI-прозу без всяких детекторов — по гладкости, «правилу трёх», симметричным конструкциям, отсутствию шероховатостей и личных деталей. **Этот файл — сырьё. Ни один абзац отсюда нельзя вставлять в пост как есть.** Прочитай, закрой файл, напиши по памяти своими словами — что помнится без шпаргалки, то и есть твой текст. Числа и оговорки потом сверь по разделу 3. Использование AI на этапе подготовки полиси явно разрешает — при сомнении добавь одну строку дисклеймера в начало поста.
